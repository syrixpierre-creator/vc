## What was built in this round
- **Back end**: PostgreSQL store for everything (transactions, advisory locks, append-only ledger and audit enforced by triggers, idempotency keys); BullMQ queues (Google sync, e-mail, maintenance) with PostgreSQL as source of truth; Redis rate limiting; all modules of the brief (contacts with several numbers, labels, history, duplicates and merge, VCF import/export, user backups, Google sync, referrals and milestones, wallet and payouts, rewards and manual fulfilment, challenges and templates, XP/levels/VIP/achievements/missions/streaks/leaderboards/share cards, notifications, announcements, support, onboarding, settings, sessions, data export, account deletion); full admin API with permission checks and audit; e-mail templates in 5 languages; alerts; 135 documented API operations (`/api/openapi.json`).
- **Front end**: rebuilt website, user app and admin console; design system (dark default + light theme, Inter + Noto Sans Arabic bundled); **every emoji replaced** by an 89-icon SVG sprite; new SVG logo set (mark, full logo, light variants, favicon, app icons, social image) generated by `scripts/brand.mjs`; strict Content-Security-Policy (no inline code), no `innerHTML`; 5 languages with Arabic right-to-left; legal pages, support page, sign-in error page, 404, web manifest.
- **Deployment**: hardened Dockerfile and Compose stack (Caddy, app, worker, PostgreSQL, Redis; internal network; read-only, non-root containers), one-command idempotent `install.sh`, encrypted backups with optional off-site copy, restore script, daily backup timer.
- **Docs**: README, deployment, Google setup, payouts runbook, security model, operations/incidents, ads policy.

## Bugs found and fixed while verifying (this round)
- Two app pages (Backups, Settings) did not load because of a syntax error; a test now parses every browser module.
- Form labels were not linked to their inputs anywhere (accessibility); fixed in the shared `field()` helper.
- The recovery-phrase guard on payout details could never trigger for PayPal/Binance; it now runs first, with a test.
- "UTC" was rejected as a time zone (users on UTC never got one saved); fixed, with a test.
- Published challenges could still be made easier before anyone qualified, contradicting the published rules; the goal can no longer be lowered nor the reward reduced after publishing, with a test.
- The Google callback answered browsers with raw JSON errors; it now shows a translated page.
- Wide tables collapsed (CSS clash), dashboard cards stretched, chart labels overlapped, a referral privacy text overstated what was shown; all fixed.

## Not verified (needs your accounts or a real server)
1. **Real Google**: sign-in and Google Contacts sync were tested only against a simulated Google (signed tokens, fake People API). Run the checks in `docs/GOOGLE_SETUP.md` §5 after installing. The Contacts scope needs Google verification before the public can use it.
2. **Real e-mail delivery** (Resend): never sent. Without `EMAIL_PROVIDER=resend` e-mails are only logged.
3. **Full VPS install**: `install.sh` was run with `--skip-system` (no apt, Docker install, ufw or systemd timer in this sandbox). Those steps are standard but untested here; run it on a fresh Ubuntu 22.04/24.04 server.
4. **Let's Encrypt certificates**: Caddy obtains them automatically for a real domain; only the local internal certificate was used here.
5. **Off-site backup copy** (`RCLONE_REMOTE`): not tested.
6. **Payouts**: nothing sends money. Payouts are manual by design; PayPal/Binance/Pix are never called by the code.
7. **Ads**: no ad network connected or approved (see `docs/ADS_POLICY.md`).
8. **Railway/Render**: described, not tried.
9. **Security**: no external penetration test.
10. **Legal texts**: written in plain language from what the code actually does, in English and French. Portuguese, Spanish and Arabic readers see the English text with a notice. Have them reviewed by a lawyer before launch.
11. **Load**: no load test. One `app` and one `worker` container are expected for launch; the money paths use database locks, so more replicas are safe, but untested.

## Deviations from the brief (decisions you may want to revisit)
- **Stack**: the brief suggested a framework stack; the project keeps its existing architecture (Node 22 + TypeScript without build, plain SQL migrations, framework-free front end). It has no build step and few dependencies (pg, bullmq, ioredis, libphonenumber-js), and everything above is tested on it. Moving to Next.js/Prisma would be a rewrite.
- **Reward model** (changes the earlier README's approved "$0.01 per referral"): implemented as the brief describes, a one-time $10.00 at 500 qualified referrals with badge/XP milestones before it; per-referral cash is off (`reward_policy.centsPerReferral = 0`, editable in Admin → Settings). Minimum withdrawal $10.00.
- **Phone numbers**: the earlier "one number per contact" became several numbers per contact (first one is the primary), as the brief describes contact management. A number cannot belong to two contacts of the same user.
- **Docker Hub rate limits**: in this sandbox base images came from Google's Docker Hub mirror; on a normal server `install.sh` pulls them from Docker Hub as usual.

## How to continue
1. Create the Google OAuth client (`docs/GOOGLE_SETUP.md`).
2. On a fresh VPS: `sudo scripts/install.sh --domain … --admin-email syrixcompany@gmail.com --google-client-id … --google-client-secret …`.
3. Sign in as the admin, run the real-Google checks, publish this month's challenges (Admin → Challenges → Drafts from templates), set the reward budget.
4. Store `ENCRYPTION_KEY` and `BACKUP_PASSPHRASE` outside the server; test a restore.
